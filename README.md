# System Diary Designer

시스템 다이어리 속지를 만들어 인쇄하는 프로그램. 설계는 [설계문서.md](설계문서.md) 참고.

저장소: https://github.com/jiing2222/Diary-Designer

## 실행

```bash
npm run dev        # 개발 서버 → http://localhost:5173
npm test           # 치수 계산 검증
npm run build      # 타입 검사 + 배포용 빌드
```

> `npx tsc --noEmit`은 아무것도 검사하지 않는다. tsconfig가 solution 스타일
> (`files: []` + `references`)이라 포함된 파일이 없다. **타입 검사는 `npm run build`로 한다.**

## 지금 어디까지 됐나

**1단계 — 인쇄 정확도 검증** 완료. 실제로 인쇄해서 자로 쟀고 50mm가 정확히 나왔다.

**2단계 — 도트와 그리드** 완료. 간격과 모양을 고르면 도트속지·그리드속지·줄노트가
나오고 PDF로 인쇄된다. 화면에 보는 것과 인쇄물에 남기는 것을 따로 켜고 끌 수 있고,
타공 안전영역을 비워둘 수도 있다.

**3단계 — 타공 위치 표시** 1~2단계에 이미 포함됐다.

**4단계 — 그리기 도구** 진행중. `양식 만들기` 탭에서 표를 그리고 글자를 넣을 수 있다.
글꼴은 Pretendard 하나가 담겨 있고, 파일로 추가하는 것은 아직 안 된다.

```
그리기(L)   점 클릭 → 점 클릭     선 (대각선도 된다)
            점에서 드래그         면 = 선 네 개
            같은 자리에 다시      지워진다

글자(T)     칸 클릭              그 칸에 글자, 모자라면 자동으로 늘어난다
            여러 칸 드래그        걸친 칸 전체가 상자
            비워두면             안 남는다
            글자를 클릭          바로 그 자리에서 고치기
            다른 도구에서 더블클릭  T모드로 바뀌며 바로 입력
            Enter 확정 · ⇧Enter 줄바꿈

고르기(V)   클릭 · Shift+클릭 · 감싸기 → 선택
            끌어서 이동 · Delete로 삭제
            하나만 고르면 끝점 손잡이가 나와 길이·각도를 바꾼다

⌘Z 되돌리기 · ⇧⌘Z 다시실행
```

굵기·색·모양(선)이나 크기·정렬·색(글자)은 위쪽 막대에서 정한다. 입력 중이면 그
상자 자체, 고른 것이 있으면 그것들, 둘 다 없으면 **앞으로 그리거나 쓸 것**의
기본값을 보여준다. `기본`을 고르면 값을 지워 [core/style.ts](app/src/core/style.ts)의
기본값을 다시 따라간다.

치수는 그리는 동안 커서 옆에, 고른 뒤에는 위쪽 막대에 나온다.
선 하나면 길이, 여러 개면 감싸는 네모의 가로 × 세로다. 왼쪽 아래에는 지금
격자가 몇 칸인지 항상 떠 있다(도트·그리드·줄 모양과 무관하게 같은 수).

여러 줄(⇧Enter)을 쓰면 줄마다 정확히 다음 도트 줄에 앉는다 — 도트 간격을
그대로 줄 간격으로 쓴다. 글자는 자기 상자를 넘칠 수 있고, **편집 화면에서는
넘친 것도 그대로 보인다** — 얼마나 넘쳤는지 알아야 다음에 뭘 할지 판단할 수
있어서다. 실제로 옆 칸을 침범하는 건 인쇄될 때뿐이다: 인쇄 미리보기와 PDF는
속지 경계에서 자른다.

`인쇄하기` 탭에는 **"실제 인쇄 모습만 보기"** 토글이 상단에 있고 **기본으로 켜져
있다.** 켜면 도트·타공 화면 설정과 무관하게 실제로 인쇄될 모습만 보여준다 —
칸 경계선, 타공 안내, 인쇄 불가 영역 표시가 전부 빠지고 도트도 실제 인쇄
크기(0.2mm)로 나온다.

인쇄할 때는 반드시 **"실제 크기 / 100%"**를 고른다. "페이지에 맞춤"이면 96~97%로 축소된다.
50mm 검증 눈금자는 1단계에서 이미 확인해서 기본은 꺼져 있다.

## 구조

```
app/src/
  core/       치수 계산. UI도 PDF도 모르는 순수 계산만 있다
    units.ts    mm ↔ pt 변환
    presets.ts  용지·속지 규격
    punch.ts    타공 위치 (속지 높이에서 자동 계산)
    layout.ts   용지 한 장에 몇 개가 들어가는지
    crop.ts     절취선·십자 마크 좌표
    grid.ts     도트 격자. 격자점 좌표와 그릴 모양을 따로 낸다
    place.ts    속지 좌표 → 용지 좌표. 회전 배치를 여기서 처리한다
    snap.ts     마우스 위치 → 가장 가까운 격자점
    objects.ts  사용자가 그린 것들 (선 · 글자)
    text.ts     글자를 어디에 놓을지. 화면과 PDF가 같은 자리를 쓰게 한다
    history.ts  실행취소·다시실행
    style.ts    색과 굵기. 화면과 PDF가 같은 값을 쓰게 한다
  pdf/        벡터로 PDF를 직접 그린다
  fonts/      PDF에 심을 글꼴 불러오기
  ui/         화면. SVG viewBox를 mm로 잡아 좌표가 곧 mm가 된다
    InsertView   속지 한 장의 내용. 편집 화면과 인쇄 미리보기가 같이 쓴다.
                 mode='edit'|'print'로 화면용 표시와 실제 인쇄 모습을 가른다
    PunchGuide   타공 안내. 두 화면이 같이 쓴다. 인쇄되지 않는다
    EditorTab    양식 만들기 화면
    PaperPreview 인쇄하기 화면. "실제 인쇄 모습만 보기" 토글이 있다
    SettingsPanel 아이콘 막대 + 말풍선 설정
    measureText.ts  입력 중인 글자 크기를 재서 상자 자동 늘어남에 쓴다
    pixels.ts       mm ↔ 화면 픽셀. core가 아닌 여기 두는 이유는 core는 화면을 몰라야 해서다
```

### 지켜야 할 원칙

**화면과 PDF는 같은 데이터를 각자 따로 그리는 두 개의 독립적인 뷰다.**
캔버스를 이미지로 떠서 PDF에 넣으면 실제 치수가 어긋난다. `export.test.ts`가 이걸 막고 있다.

**모든 좌표는 mm다.** 픽셀이나 포인트 값이 `core/`에 저장되는 일은 없어야 한다.
변환은 그리는 순간에만 일어난다.

**여백은 입력받지 않는다.** 도트 격자의 여백도, 타공의 상하 여백도 마찬가지다.
간격을 정하면 여백은 저절로 결정되는 종속 변수라, 따로 받으면 값끼리 모순이 생긴다.

**스냅은 보이는 모양과 무관하다.** 화면에 도트로 보이든 줄노트로 보이든 붙는 자리는
언제나 `gridLattice`가 낸 격자점이다. 이래야 어떤 스타일에서도 같은 위치에 그려진다.

**화면의 도트는 일부러 크고 진하다.** 인쇄되는 0.2mm를 그대로 그리면 1픽셀도 되지 않아
작업할 수가 없다. **위치는 조금도 다르지 않고 굵기와 색만 다르다.** "같은 데이터를 각자
그리는 두 개의 뷰"라는 원칙은 데이터가 같다는 뜻이지 똑같이 보여야 한다는 뜻이 아니다.
인쇄물이 어떻게 보일지는 화면이 아니라 실제로 뽑아서 판단한다.

**타공 상하 여백은 입력받지 않는다.** 구멍 간격 19mm는 바인더 규격이라 고정이고
구멍은 세로 정중앙에 있으므로, 여백은 속지 높이에서 저절로 결정되는 종속 변수다.
브랜드마다 M6 세로가 125~128mm로 제각각이라 고정값을 두면 금방 틀어진다.
