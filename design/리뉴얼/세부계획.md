## 문서 구성과 설계 기준

메인 메뉴별로 Create / Library / Learn을 나눈다. 현재 구체화 대상은 **Create**다. 최신 제안은 아래 A0의 상단 상황별 도구막대 구성이다. 파일을 늘리지 않고 이 문서 안에서 메뉴별로 구분한다.

- 사용자 요청은 요구사항으로, 구체적인 배치·동작은 설계 제안으로 구분한다.
- 현재 Rings는 기능과 데이터 동작을 파악하는 참고 자료다. 기존 UI의 위치·크기·형태를 유지할 필요는 없으며 새로 디자인할 수 있다.
- 기능을 찾기 쉽게 재배치하고, 불필요한 설정 노출을 줄인다. UI 정리만을 이유로 기존 기능이나 저장 데이터를 삭제하지 않는다.
- 이번 요청의 ‘굵기 삭제’는 오토필드의 글자 굵게 버튼 제거로 반영한다. 공유 글자 설정을 쓰는 일반 텍스트에도 동일한 UI를 적용하는 안을 제안한다. 선·도형의 선 두께는 유지한다.

## A. Create — 새 작업과 제작

### A0. 최신 화면 제안 — 넣기는 왼쪽, 꾸미기는 위쪽

사용자의 상단 텍스트 바 아이디어를 확장해 **선택한 요소에 따라 바뀌는 도구막대**를 편집 영역 상단에 둔다. 기존의 긴 좌측 설정 목록을 단순히 재배열하는 대신, 탐색·삽입과 꾸미기를 공간적으로 분리한다.

결정 (2026-09-27): **Canva식 상단 막대 + 팝오버**로 한다. 글꼴·크기·색·정렬처럼 자주 쓰는 것만 막대에 두고, 간격·선 모양처럼 숫자가 필요한 것은 팝오버 안에 라벨과 함께 둔다. 미리캔버스식(왼쪽 패널이 속성으로 바뀜)은 넣기 패널이 가려져, 오토필드처럼 왼쪽에서 날짜를 고르며 위에서 모양을 바꾸는 흐름에 맞지 않는다.

`상단 전역 바: Rings / 작업 이름 / 저장 상태 / 실행 취소 / Print`

`좌측: 도구 → 넣을 내용·종류·자료 | 편집 영역 상단: 선택 대상의 꾸미기`

`좌측 하단: 작업 팔레트          | 중앙: 페이지와 페이지별 관리 버튼`

#### 화면 영역별 책임

- **좌측 도구 패널**: 무엇을 넣을지 찾고 선택한다. 다른 작업의 페이지·이미지는 미리보기, 요소는 모양, 오토필드는 날짜 연결과 표시 형식에 집중한다.
- **상단 상황별 바**: 글꼴·크기·정렬, 선 두께·선 모양, 이미지 크기 등 선택 대상의 외형을 조절한다. 캔버스 바로 위에서 위치를 유지한다.
- **작업 팔레트**: 좌측 하단에 유지한다. 상단에는 필요할 때 ‘글자 A’, ‘선 기본’, ‘채움 B’ 같은 적용 대상만 표시하고 색상 편집기를 중복 배치하지 않는다.
- **페이지 설정**: 문서 전체 또는 페이지 자체의 설정이므로 왼쪽에 둔다. 요소 꾸미기와 혼동하지 않는다.
- **페이지 메뉴**: 복제·여러 장 복제·저장·삭제는 해당 페이지 가까이에 유지한다.

#### 바의 상태

| 선택 상태 | 상단에 보이는 것 | 펼쳤을 때 |
|---|---|---|
| 필드·일반 글자 | 글꼴 / 크기 pt / 가로 정렬 / 색상 역할 | 간격: 줄간격·자간 mm, 배치: 세로 정렬·회전 |
| 달력 | 글꼴 / 자동 맞춤·크기 / 색상 역할 | 달력 행 간격·자간, 적용 대상은 전체를 기본으로 검토 |
| 선 | 두께 mm / 실선·파선·점선 / 선 색상 역할 | 배치·회전 |
| 도형·표 | 테두리 두께·모양 / 채움 / 색상 역할 | 모서리·불투명도; 표에서 지원하지 않는 속성은 숨김 |
| 체크박스 | 아이콘 크기 mm / 테두리 두께 / 색상 역할 | 배치 |
| 이미지 | 가로·세로 mm / 비율 유지 / 교체 | 회전·배치 |
| 선택 없음 | 선택 안내 또는 새로 만들 요소의 기본 스타일 | 전역 기능을 억지로 채우지 않음 |
| 혼합 선택 | 공통으로 적용 가능한 속성만 | 혼합 값 표시, 변경한 속성만 반영 |

최상단 작업 바와 상황별 바는 역할을 구분한다. 텍스트 설정은 왼쪽과 위쪽에 중복 노출하지 않는다. ‘간격’ 버튼을 열면 줄간격과 자간을 함께 조절하되 모든 숫자 칸을 항상 펼치지는 않는다.

#### 추가 아이디어 — 검토용

1. **글자 스타일 보관**: ‘섹션 제목’, ‘작은 캡션’처럼 글꼴·크기·간격·색상 역할을 저장해 반복 페이지에서 재사용한다. 문서 전체 변경과의 연결 범위는 별도 검토한다.
2. **모양 복사**: 내용이나 날짜 연결을 바꾸지 않고 선택 요소의 꾸미기만 다른 요소에 적용한다. 기존 기능으로 간주하지 않으며 2차 우선순위다.
3. **형식 칩의 실제 날짜 미리보기**: 월·일·주·요일을 고르면 현재 페이지 날짜를 예시로 사용해 선택 직후 결과를 예측할 수 있게 한다.
4. **페이지 추가의 작은 선택 메뉴**: 빈 페이지 / 다른 작업에서 / 날짜로 만들기를 페이지 아래 한 진입점으로 모은다.
5. **복제 시 두 가지 목적 구분**: 한 번 누르는 복제는 내용 그대로, ‘여러 장 만들기’에서는 동일 복제와 날짜 진행을 분명히 구분한다.
6. **선택 범위를 짧게 표시**: ‘날짜 글자 1개’, ‘메모 양식 12페이지 공통’처럼 실제 수정 범위를 바 가까이에 보여준다. 공통 수정 연결이 확정된 경우에만 후자를 제공한다.

#### 스케치 읽는 법과 한계

대화에 제공한 화면 스케치는 왼쪽 여섯 메뉴를 전환하면 해당 삽입 패널과 상단 바 구성이 바뀐다. 오토필드의 종류·형식과 일부 글자 크기·자간·색 적용은 미리보기로 확인할 수 있다. 페이지 추가·인쇄·업로드 등은 다음 동작을 안내하는 구성 예시이며 실제 편집 기능을 실행하지 않는다. A5와 날짜는 설명용 예시다. 최종 미감·모바일 편집·정확한 인쇄 치수는 검증 대상에 포함하지 않았다.

좁은 화면에서는 중요 도구를 남기고 나머지를 더보기로 접는다. 스케치는 비교를 위해 패널을 위아래로 배치하지만 이를 모바일 제품의 최종 설계로 확정하지 않는다.

### A1. 전체 화면과 진입

- 상단: 작업 이름, 현재 규격, Print 액션.
- 좌측: 도구별 자료·내용 선택과 페이지 설정.
- 중앙: 페이지가 세로로 이어지는 편집 영역.
- 각 페이지: 페이지 정보와 관리 메뉴, 페이지 추가 진입점.
- 좌측 하단: 공통 색상 관리 영역을 두는 방향.

설계 제안: 페이지 목록은 상시 패널 대신 필요할 때 여는 ‘페이지 한눈에 보기’로 제공한다. 별도의 오른쪽 설정 패널을 기본 구조에 추가하지 않는다.

좌측 메뉴 재구성의 우선 대상은 **큰 탭 이름이나 개수보다 탭 내부 세부 항목의 순서·그룹·표현**이다. 앞서 논의한 큰 탭 축소안은 확정안으로 취급하지 않는다.

기존 좌측 도구는 기능 범위를 파악하는 출발점이다. 새 UI는 아래처럼 구성하는 안을 검토한다.

- 기본 규격은 개인화 질문에서 정한 사용자의 주 사용 다이어리 크기를 따른다.
- 상단은 작업 이름·저장 상태·규격·실행 취소/다시 실행·Print로 정돈한다. 저장 상태 표시는 설계 제안이다.
- 좌측 도구의 후보 순서는 페이지 설정 → Library(다른 작업) → 요소 → 텍스트 → 이미지 → 오토필드다. 최종 명칭과 순서는 시안 검토 후 정한다.
- 선택은 기본 조작으로 제공하고, 선택 대상에 따라 상단 바가 해당 꾸미기 속성으로 바뀐다. 왼쪽은 필요한 내용 설정을 보여준다. 상시 독립 Select 탭 유지 여부는 시안에서 검토한다.
- 속성 패널 상단에 ‘새 요소에 적용 / 선택한 1개에 적용 / 선택한 3개에 적용’을 구분해 표시한다.
- 인쇄용 용지 설정은 제작 도구 목록에서 분리해 Print에 둔다.

#### 결정 (2026-09-28) — 편집기 뼈대

```text
┌ ☰ 파일 · 작업 이름 · ☁ 저장됨 · ↶ ↷ · A5 ······························ [Print] ┐
│ 레일      │ 패널              │ [ 상황별 막대: 글꼴 · 10pt · 색 · 정렬 · 간격▾ ]     │
│ Page      │                   │   1장 앞면 (오른쪽에 혼자)                            │
│ Draw      │ (레일에서 고른     │   [ 1장 뒷면 | 2장 앞면 ]  ← 펼침면                    │
│ Text      │  도구의 내용)      │   [ 2장 뒷면 | 3장 앞면 ]                              │
│ AutoField │                   │   [ + 페이지 추가 ▾ ]                                  │
│ Image     │───────────────────│                                                        │
│ Library   │ Colors (고정)      │                                                        │
└───────────┴───────────────────┴ 여백 4.2mm · 도트 27×40칸 ·· 58% · 3 / 33 · ⊞ ────┘
```

- **레일**: 가장 왼쪽 아이콘 줄. **패널**: 레일에서 고른 도구의 내용이 펼쳐지는 칸.
- 레일 이름은 영어, 순서는 **Page · Draw · Text · AutoField · Image · Library**. Page는 작업을 시작할 때 먼저 정하고, Library는 가끔 쓰므로 맨 아래.
- **Select 버튼은 없앤다.** 다른 도구를 고르지 않으면 늘 선택 상태다(Canva·미리캔버스와 같음).
- **Page** = 기존 Insert 탭(속지 설정). 패널을 하위 탭 **Background / Margin / Punch / Guide**로 묶는다(A5).
- **속지 크기는 상단 바의 다이어리 칩(예: `검정 바인더 ▾`)에서만 바꾼다.** 모든 페이지에 영향을 주는 큰 변경이라 Page 패널에 두지 않는다. 칩에는 규격 대신 등록한 다이어리 이름이 보인다(기본계획 7장).
- **계산된 여백과 칸 수는 화면 하단 상태 막대에 늘 보인다.** 이 앱에서 중요한 정보라 접어두지 않는다.
- **Draw** = 기존 Draw 탭. 타일: Line / Shape / Table / Checkbox.
- **Image**는 기존 Image 탭과 같은 역할(썸네일 목록·업로드).
- **AutoField**는 A4.2의 타일 구성.
- **꾸미기 설정은 모든 요소에서 상단 막대**에 둔다. 선·도형도 글자와 같은 자리에서 설정한다. 막대 자리는 선택이 없어도 늘 비워둬 화면이 들썩이지 않게 한다. 직접 써보고 불편하면 다시 정한다(대안: 모두 왼쪽 패널).
- **Text** 패널: 글자는 지금처럼 도구를 고르고 페이지를 눌러 그 자리에 놓는다(mm 정확도). 패널에는 **저장한 글자 스타일**을 두고, 사용자가 추가·삭제한다(A8).
- **파일 메뉴는 왼쪽 위**(☰)에 둔다. 파일로 저장·불러오기, 작업 크기 변경 등. 오른쪽 위에는 Print 버튼 하나만 둔다.
- ‘인쇄 준비’의 이름은 **Print**다.
- 작업 색상(Colors)은 패널 아래에 **늘 보이게 고정**한다(A13). POINT 색은 개수 제한 없이 계속 추가할 수 있다.
- 페이지는 **펼침면**으로 보인다(A11).

### A2. 현재 기능 분석과 재배치 지도

아래는 소스의 실제 컨트롤과 연결 구조를 확인한 결과다. 각 항목의 새 배치는 설계 제안이며 전체 동작을 실행 검증했다는 의미는 아니다.

| 현재 메뉴·영역 | 확인한 기능 | 정리 방향 |
|---|---|---|
| Insert | 규격·가로/세로, 도트/그리드/가로줄/세로줄, 간격·칸 수·여백·등분 안내, 타공·안전영역, 화면/인쇄 표시 | 페이지 설정에서 규격 / 바탕 / 타공 / 안내로 그룹화 |
| Template | 같은 규격 양식 선택, 전체 관리로 연결 | 목록은 Library로, 편집기에서는 ‘다른 작업에서 페이지 가져오기’(A6) |
| Image | 이미지 목록·추가·배치·교체, 가로/세로·회전 | 이미지 선택과 선택 이미지의 크기·배치를 분리; 파일 관리는 Library 연결 |
| Select | 선택 대상별 속성, 다중 선택, 삭제·잠금·그룹, 선택 크기 표시 | 기본 선택 동작과 대상별 속성으로 통합; 대상 없음/복수 선택 상태 정의 |
| Draw | 선·도형, 표, 체크박스; 두께·선 모양·모서리·채움·투명도·아이콘 크기 | 요소 종류 먼저 선택, 해당 종류 설정만 노출 |
| Text | 글꼴·굵게·pt 크기·mm 줄간격·가로/세로 정렬·회전·색, 자동필드 전환 | 명시적 라벨과 공통 글자 설정; 자간 추가, 글자 굵게 UI 제거안 |
| AutoField / Calendar | 시작 요일·요일 언어·글꼴·색·크기 배율·줄간격 배율·자간·인접 월·제목 | 실제 월 미리보기 → 내용 → 글자 → 간격 순서 |
| AutoField / Field | 서식 목록, 0부터 시작하는 값 순번, 텍스트 공통 속성 | 월/일/주/요일 분류 → 표시 예시 → 날짜 연결 → 글자 설정 |
| Paper / 반복 | 한 번·동일 양식 반복·날짜/달력 세트, 기간·진행 단위·페이지당 값 | 페이지 복제와 날짜로 페이지 생성은 제작 화면으로 이동 |
| Paper / 배치 | 용지 크기·방향·여백, 간격·회전·정렬·재단선·눈금·재단 후 순서 | Print의 기본 설정과 고급 설정으로 분리 |
| View / Slot / Print 편집 | 화면 안내, 양면 보기, 칸 배정, 출력 페이지 개별 편집 | 화면 보기·인쇄 배치·페이지 내용 편집으로 역할 분리 |

### A3. 모든 도구에 적용할 속성 UI

- 흐름은 **무엇을 넣는가 → 내용 → 모양 → 간격·배치**로 통일한다. 앞의 두 단계는 왼쪽, 모양과 간격·배치는 상단 바에서 처리한다.
- 입력칸 위나 옆에 라벨을 항상 표시한다. 단위만 보이는 ‘pt’, ‘mm’, ‘100%’ 입력을 만들지 않는다.
- 숫자는 직접 입력과 작은 증감 버튼을 함께 제공한다. 숫자·단위는 한 입력 그룹으로 묶는다.
- 글자 크기는 pt, 줄간격·자간·실제 치수는 mm로 표시하는 방향이다. 아래 값은 배치 예시이며 기본값 확정이 아니다.

`글자 크기 [10 pt]    줄간격 [4.5 mm]    자간 [0 mm]`

- 좁은 패널에서는 글자 크기를 한 줄, 줄간격·자간을 다음 줄에 배치한다.
- 줄간격은 줄 기준선 사이 거리, 자간은 글자 사이 추가 간격으로 설명한다. 한 줄 텍스트에는 줄간격을 비활성화하거나 고급 항목으로 접는다.
- 정렬은 라벨 있는 아이콘 그룹, 표시 여부는 체크/스위치, 상호 배타적 종류는 작은 전환 버튼을 사용한다.
- 복수 선택에서 값이 다르면 ‘혼합’으로 표시하며, 사용자가 변경한 속성만 적용한다.
- 색상 편집은 좌측 하단 팔레트로 모으되 적용 대상이 글자/선/채움 중 무엇인지 표시한다.
- 입력 오류는 해당 칸에서 안내하고, 숫자를 입력하는 중 포커스를 빼앗지 않는다.

### A4. 오토필드 — 우선 설계 대상

#### A4.1 현재 구조에서 해결할 문제

- 현재 Field 서식 15개가 날짜·요일·월·주차 구분 없이 한 목록에 들어 있다.
- 예시 ‘3’과 ‘15’, ‘월’은 종류를 먼저 알지 못하면 의미가 모호하다.
- 필드의 값 순서는 내부 기준인 0부터 표시된다. 사용자는 ‘첫째 날짜’로 이해하는 편이 쉽다.
- 현재 필드는 일반 텍스트 설정을 공유한다. pt 글자 크기와 mm 줄간격은 있으나 일반 텍스트/필드용 자간 속성은 확인한 모델과 컨트롤에 없다.
- 달력에는 이미 mm 자간이 있다. 달력의 글자 크기와 행 간격은 비율 방식이어서 텍스트와 표현이 다르다.
- 필드 설정의 안내는 인쇄 때 값이 채워지는 구조를 전제로 한다. 새 제작 흐름에서는 실제 날짜를 편집 중 보여줘야 한다.

#### A4.2 패널 공통 구조

결정 (2026-09-28): 레일 이름은 **오토필드**로 유지한다. 패널 맨 위에 종류 타일을 두고, 날짜는 월·일·주·요일로 쪼개 따로 고른다.

```text
AutoField
[ Year ] [ Month ] [  Day  ]
[ Week ] [Weekday] [ D-day ]
[Calendar] [Page No.] [ Moon ]
```

- 타일 9개를 3×3으로 둔다(Canva 요소 패널처럼). 타일 이름은 레일처럼 영어.
- **Year**(2027)는 신규. 지금은 `2027-03-15` 안에만 연도가 있고 연도만 따로 쓰는 형식이 없다.
- **주간 범위**(10/6 – 10/12)는 Week 타일의 표시 형식으로 추가한다(신규).
- D-day는 A4.7.
- 타일을 고르면 그 아래에 해당 종류의 설정만 보인다. 월·일·주·요일은 A4.3, 달력은 A4.4, 페이지 번호·달 모양은 A4.7.

(이전 안) 맨 위의 큰 Calendar / Field 버튼을 작은 ‘달력 / 필드’ 전환으로 정리한다. 그 아래에는 선택한 종류의 내용만 표시한다. 한쪽을 선택한다고 이미 놓인 반대 종류의 요소를 변환하지 않는다.

미선택 상태는 새로 넣을 요소 설정, 선택 상태는 기존 요소 수정임을 표시한다. 사용자에게 내부 자리표시 코드를 기본 노출하지 않는다.

#### A4.3 필드: 종류와 표시 형식

사용자 요청: 월·일·주·요일을 더 이해하기 좋은 UI로 구성한다.

| 종류 버튼 | 표시 형식 예시 — 기존 기능 보존 | 새 UI |
|---|---|---|
| 월 | 3 / 3월 / MAR / March | 예시 칩을 골라 적용 |
| 일 | 15 / 3/15 / 3월 15일 / 2027-03-15 | 일만 표시와 전체 날짜 표현을 함께 탐색 |
| 주 | 11주차 / W11 / Week 11 | ‘주차’라는 설명과 예시 표시 |
| 요일 | 월 / 월요일 / Mon / Monday | 한글·영어 결과를 직접 보고 선택 |

선택 순서: 왼쪽의 **종류 → 표시 형식 → 어떤 날짜를 사용할지**, 이후 상단 바의 **글자 모양**.

- 예시 칩은 가능하면 현재 미리보기 날짜로 갱신한다.
- ‘주’는 현재 구현상 연중 주차다. 1월 1일부터 7일씩 계산하는 기존 규칙을 ISO 주차나 월별 주차로 조용히 바꾸지 않는다. 다른 주차 기준 지원 여부는 미정이다.
- 단독 연도 필드, 자유 서식 조합 등 기존 목록에 없는 형식은 신규 기능으로 별도 검토한다.
- ‘0번째’ 대신 ‘이 페이지의 첫째 날짜 / 둘째 날짜…’처럼 보여주고 내부 순번과 연결한다.
- 같은 날짜의 월·일·요일 필드를 따로 놓으면 모두 같은 날짜에 연결할 수 있어야 한다. 배치할 때마다 날짜를 무조건 증가시키지 않는다.
- ‘다음 날짜로 이어 배치’는 별도 선택으로 제공하는 안을 검토한다. 위클리처럼 서로 다른 날짜가 필요한 경우에 사용한다.

필드 화면의 좌측·상단 배치 예시:

`[달력 | 필드]`

`종류     [월] [일] [주] [요일]`

`표시     [15] [3/15] [3월 15일] [2027-03-15]`

`날짜 연결  [이 페이지의 첫째 날짜 ▾]   미리보기: 3/15`

`상단 바: 글꼴 [선택 ▾]   글자 크기 [10 pt]`

`상단 간격 팝오버: 줄간격 [4.5 mm]  자간 [0 mm]`

`정렬 [왼쪽 / 가운데 / 오른쪽]   배치 [펼치기]`

#### A4.4 달력: 내용과 표현 분리

1. **기준 월**: 페이지에 연결된 연·월과 실제 미리보기. 여러 달 생성은 별도 액션.
2. **달력 구성**: 시작 요일, 요일 언어, 이전·다음 달 표시.
3. **제목**: 자동 / 직접 입력 / 숨김을 명시적으로 구분. 빈 입력의 의미에 의존하지 않는다.
4. **글자 — 상단 바**: 글꼴과 글자 크기. 크기는 ‘자동 맞춤 / 직접 지정 pt’ 방식을 제안한다.
5. **간격 — 상단 팝오버**: 달력의 주 행 간격과 자간. mm 입력을 제안하되 제목·요일·주 행의 간격을 무엇으로 조정할지 시안과 출력 결과로 검토한다.

현재 크기 배율·행 간격 배율을 숫자만 pt·mm로 치환하면 안 된다. 기존 달력의 상자 크기와 실제 배치를 바탕으로 환산하거나 기존 자동 동작을 유지해야 한다. 직접 지정 시 넘침을 알려야 한다.

달력 전체 색상 변경은 공통 팔레트와 연결한다. 제목·요일·특정 날짜를 각각 선택해 색을 바꾸는 기능은 아직 사용 범위가 확정되지 않았다. 확정 기능으로 표시하지 않는다.

#### A4.5 굵기·단위·자간 요구사항

- 오토필드의 글자 굵게 버튼은 제거한다.
- 일반 텍스트도 동일한 글자 패널을 쓰는 것을 제안한다. 과거 문서의 bold 값을 지워 외형을 바꾸는 것은 별도 문제이며 보존 방식 검토가 필요하다.
- 필드와 일반 텍스트에 자간 mm 설정을 추가한다. 달력의 기존 자간도 같은 라벨·입력 스타일로 통일한다.
- pt는 글자 크기, mm는 줄간격·자간임을 라벨과 함께 표시한다.
- 자간은 화면 표시뿐 아니라 선택 상자·텍스트 측정·줄바꿈·저장/재열기·PDF에도 일관되게 적용해야 한다.
- 음수 자간 허용 범위, 입력 증감 폭, 기본값과 최대·최소값은 구현 전 결정한다.

#### A4.6 날짜로 페이지 만들기와 개별 수정

##### 사용자 요청

Print에서 날짜가 채워진 결과를 확인하고 색상 등을 개별 수정해야 하는 현재 흐름을 단순화한다. 여러 페이지 제작과 수정이 제작 화면 안에서 이어져야 한다.

##### 설계 제안

1. 페이지에 날짜·달력을 배치한다.
2. 기간과 페이지당 날짜 진행 규칙을 지정한다.
3. 생성될 페이지 수와 날짜를 확인한다.
4. 실제 날짜가 들어간 페이지들을 제작 화면에 생성한다.
5. 특정 페이지나 공통 디자인을 수정한다.

예: M5 데일리 디자인 → 10월 기간 지정 → 31페이지 생성 → 특정 날짜의 글자색 수정 → Print.

공통 디자인 변경에는 ‘이 페이지만 / 같은 양식으로 만든 페이지 전체’와 같은 적용 범위를 검토한다. 이 범위 선택을 모든 조작마다 반복적으로 묻지 않도록 UI를 설계해야 한다.

##### 결정 (2026-09-27)

1. **개별 수정은 고친 요소 하나만 원본에서 분리한다.**
   - 예: 10/1~10/14를 생성한 뒤 10/5의 날짜 필드 색만 바꾼다. 이때 분리되는 것은 그 필드 하나다.
   - 10/5 페이지의 나머지 요소는 원본 양식을 계속 따른다. 원본을 고치면 10/5에도 반영된다.
   - 원본을 처음부터 다시 만들고 싶으면 생성된 페이지를 지우고 다시 생성한다. 이 경로는 별도 기능 없이 가능하다.
   - 현재 코드는 페이지 단위로 분리한다(`pageOverrides`: 한 곳을 고치면 그 페이지 전체가 분리). 리뉴얼에서 요소 단위로 바꾼다.
2. **편집 화면의 자동필드는 실제 값으로 보인다.**
   - 현재의 `⟨+D0⟩` 같은 자리표시 대신 `10/1`처럼 선택한 서식이 적용된 실제 글자를 보여준다.
   - 생성된 각 페이지는 자기 날짜를 표시한다(10/1, 10/2 …).

3. **원본 양식에 보일 날짜**: 기간을 정하기 전에는 오늘 날짜로 보이고, 기간을 정하면 첫 날짜(예: 10/1)로 바뀐다.
4. **분리되는 범위**:
   - 필드의 모양(색·글꼴·크기 등)만 바꾸면 그 필드는 원본에서 분리되지만 날짜 값은 계속 자동으로 채워진다.
   - 글자 내용을 직접 고치면(예: ‘10/5 생일’) 그 필드는 고정 글자가 된다. 이후 날짜 진행과 무관하다.
5. **필드는 오토필드 도구로만 만든다.** 글자 안에 `<+D0>`를 직접 쳐서 필드를 만드는 기능(`FIELD_PATTERN`·`parseFieldText`)은 없앤다. 대신 오토필드 도구를 더 쓰기 편하게 만든다(A4.3의 종류 → 표시 형식 → 날짜 연결 흐름).
6. **자동필드 구별은 선택했을 때만 한다.** 선택 테두리를 일반 텍스트 상자와 다른 색으로 표시한다. 선택하지 않은 상태에서는 밑줄·아이콘 등 어떤 표시도 붙이지 않는다 — 디자인하는 동안 화면이 인쇄 결과와 같아 보여야 하기 때문이다. 이 표시는 인쇄물에 나오지 않는다. 구체적인 색은 디자인 문서에서 정한다.

미정:

- 공통 디자인과 개별 수정의 연결 방식 — 요소 단위 분리로 결정(위 참조). 공통 수정의 적용 범위 UI는 남음.
- 기간 변경·재생성 시 개별 수정 보존 방식.
- 날짜가 제거되거나 순서가 바뀔 때 수정 내용의 귀속 기준.
- 자동 생성된 묶음 사이에 다른 페이지를 삽입하는 동작.
- 공통 색상 팔레트 변경과 페이지 한정 변경의 관계.

#### A4.7 새 종류 — 페이지 번호, 달 모양

사용자 요청 (2026-09-28): 오토필드에 페이지 번호와, 날짜에 맞춘 달 모양을 추가한다.

**페이지 번호**
- 이번 리뉴얼로 페이지가 편집 화면에 실제로 생기므로 번호를 바로 보여줄 수 있다.
- 형식 후보: `3` / `3 / 33` / `p.3`. 시작 번호와, 표지처럼 번호를 세지 않을 페이지를 정할 수 있어야 하는지 검토한다.

**달 모양**
- 글자가 아니라 **도형**이다. 날짜로 달의 위상(차고 기우는 정도)을 계산해 원과 그림자 모양으로 그린다. 이미지 파일을 쓰지 않는다.
- 계산과 모양은 core에서 한 번만 정하고, 화면과 PDF가 같은 결과를 그린다(CLAUDE.md 원칙).
- 크기(mm)·색은 다른 도형처럼 상단 막대에서 바꾼다.
- 표현 단계 후보: 8단계(삭·초승·상현·…)로 끊어 그리기 / 날마다 실제 비율대로 그리기. 다이어리에서 흔한 것은 8단계다.
- 기준 시간대는 한국(KST).

### A5. 페이지 설정 — 기존 Insert

설계 제안 순서:

결정 (2026-09-28): 규격은 상단 바 규격 칩으로 옮기고, 아래 2~5를 하위 탭 Background / Margin / Punch / Guide로 묶는다. 치수 확인(계산된 여백·칸 수)은 하단 상태 막대에 늘 보인다.

3. **여백**: 최소 여백과 실제 계산된 여백을 구분. 끝까지 채우면 불필요한 최소 여백 입력 숨김.
4. **타공**: 구멍 수, 균등/묶음 배치, 해당할 때만 묶음 간격, 안전영역.
5. **안내**: 도트·타공 화면 표시, 등분 안내. ‘화면에만 표시’와 ‘출력에 포함’을 분리.

뒷면이 없을 때 도트만 출력하는 옵션은 Print로 이동한다. 상세 계산 결과는 접은 ‘치수 확인’에 배치한다.

### A6. 다른 작업에서 페이지 가져오기 — ‘내 템플릿’ 대신

결정 (2026-09-27): ‘내 템플릿’과 ‘템플릿으로 저장’을 두지 않는다. 다시 쓰고 싶은 페이지는 저장한 작업에서 가져온다. Canva·미리캔버스도 개인용 템플릿 없이 이 구조다([레퍼런스분석](./레퍼런스분석.md)).

#### 설계 제안

- 편집기 왼쪽 레일에 Library 패널을 둔다. 폴더와 작업 목록을 보고, 작업을 펼쳐 페이지 썸네일을 본다.
- 원하는 페이지(여러 장 선택 가능)를 골라 현재 작업의 선택한 위치 뒤에 넣는다. 현재 페이지를 덮어쓰지 않는다.
- 가져온 페이지는 **복사본**이다. 원래 작업을 고쳐도 가져온 페이지는 바뀌지 않는다.
- 앞뒤가 짝인 페이지는 짝째로 가져온다.
- 날짜 페이지를 가져올 때는 날짜 규칙(양식)만 가져오고, 기간은 새로 정하는 안을 검토한다.
- 페이지 아래 ‘+ 페이지 추가 ▾’에도 ‘다른 작업에서’ 진입점을 둔다.

미정: 다른 규격 작업에서 가져올 때의 처리(막을지, 맞춰 줄일지), 가져온 페이지의 색이 현재 작업 팔레트와 다를 때.

### A7. 요소 — 선·도형·표·체크박스

왼쪽에 모양 미리보기 타일을 두고 아래 속성은 선택 후 상단 바에 표시한다. 큰 세로 버튼을 나열하지 않고 선·도형·표·체크박스를 한눈에 비교하게 한다.

- 첫 줄에서 종류를 고르고, 종류별 미리보기 아이콘을 통일한다.
- **선**: 두께 mm → 실선/파선/점선. 색상은 하단 팔레트의 선 색에 연결.
- **도형**: 모서리 모양 → 테두리 두께·선 모양 → 채움 여부·불투명도. 채움이 없으면 관련 설정 숨김.
- **표**: 기존 격자 기반 생성·분할 동작을 보존하고, 테두리/내부 선의 공통 두께·선 모양과 외곽 모서리를 정리한다. 행·열 직접 입력이나 개별 셀 편집은 신규 제안이며 현재 지원으로 간주하지 않는다.
- **체크박스**: 아이콘 미리보기 → 아이콘 크기 mm → 테두리 두께. 선택한 모양이 분명하게 보이게 한다.
- 선 두께는 글자 굵게와 다른 속성으로 유지한다.

### A8. 텍스트

왼쪽은 저장한 글자 스타일에 집중한다. 결정 (2026-09-28): 글자 스타일(글꼴·크기·간격·색 역할)을 사용자가 **추가·삭제**할 수 있다. 스타일을 누르면 그 스타일로 글자를 놓는다. Canva식 ‘제목 추가’ 버튼(가운데에 대충 놓기)은 두지 않는다. 아래 꾸미기는 상단 바와 팝오버로 옮긴다.

설계 제안: 글꼴 → 글자 크기 pt → 가로 정렬 → 줄간격·자간 mm → 펼친 배치 설정의 세로 정렬·회전 순서.

일반 텍스트는 직접 입력에 집중한다. 자동필드로 바꾸기는 상시 체크박스 대신 보조 메뉴로 이동하는 안을 검토한다. 변환 시 현재 글자와 날짜 연결이 어떻게 바뀌는지 보여준다. 글꼴 선택에는 Library의 등록 글꼴을 사용하고 관리로 연결한다.

### A9. 이미지

왼쪽은 이미지 썸네일 목록과 추가, 상단은 선택 이미지의 크기·비율·교체·회전으로 역할을 나눈다.

설계 제안: 이미지 미리보기 목록과 추가 → 선택 이미지 교체 → 가로·세로 mm와 비율 유지 → 회전 순서. ‘비율 유지’ 노출은 새 UI 제안이며 현재 동작과 함께 검토한다.

Library는 파일 관리, Create는 페이지에 넣기·크기 조절·배치를 담당한다. 자르기·필터·배경 제거는 확인한 기능에 없으므로 이번 범위에 자동 추가하지 않는다.

### A10. 선택과 공통 조작

- 대상이 없으면 짧은 선택 안내만 표시한다.
- 단일 선택은 대상 종류의 설정, 같은 종류 복수 선택은 공통 설정을 표시한다.
- 여러 종류 혼합 선택은 적용 가능한 색상 등 공통 속성만 표시한다. 관련 없는 설정은 노출하지 않는다.
- 삭제·잠금/해제·그룹/해제는 선택에 맞는 액션으로 제공한다.
- 화면만 회전하는 기능과 실제 요소 회전, 인쇄 방향 변경을 명확히 구분한다.
- 실행 취소/다시 실행이 페이지 구조 변경과 편집에 어떻게 적용되는지 정의한다.

### A11. 페이지 관리

#### 사용자 요청

- 추가·삭제·메뉴를 각 페이지에 둔다.
- 미리캔버스·캔바를 화면 구성의 참고 대상으로 삼는다.
- 별도 영역으로 과도하게 분리하지 않고 단순하게 유지한다.

#### 설계 제안

- 페이지 위: 이름·번호, 복제 버튼, 더보기 메뉴.
- 페이지 아래 또는 페이지 사이: ‘＋ 페이지 추가’.
- 더보기: 여러 장 복제, 위·아래로 이동, 삭제.
- 삭제 후 실행 취소 제공.
- 페이지 순서 변경과 여러 페이지 선택을 위한 ‘페이지 한눈에 보기’는 필요할 때 연다.
- 도구와 상단 액션은 고정하고 중앙 페이지 영역을 스크롤한다.

결정 (2026-09-28): 중앙 편집 영역은 **펼침면**으로 보인다. 다이어리를 펼쳤을 때처럼 왼쪽에 앞장의 뒷면, 오른쪽에 다음 장의 앞면이 나란히 놓인다. 첫 장의 앞면은 오른쪽에 혼자 놓인다. 어느 면이 어느 종이의 앞뒤로 인쇄되는지는 앱이 계산한다(지금 앱의 펼침면 보기와 같은 방식). 단면 전용 작업의 표시 방식은 따로 정한다.

미정: 상시 표시와 마우스 접근 시 표시의 구분, 모바일 조작, 여러 페이지 선택 방식, 긴 작업에서의 탐색 방식.

### A12. 여러 장 복제

#### 사용자 요청

반복되는 페이지가 많으므로 n개를 입력해 자동으로 복사한다. 기본계획의 반복 페이지 내용은 이 절과 자동필드·페이지 가져오기·단면/양면 절로 통합해 관리한다.

#### 설계 제안

- 입력값은 ‘추가할 페이지 수’로 표현한다.
- 예: 10 입력 시 ‘현재 페이지 뒤에 10페이지를 추가합니다’ 표시.
- 원본은 유지하고 뒤에 복사본을 삽입한다.
- 앞뒤가 묶인 구성은 ‘세트 수’로 입력한다.
- 복제는 내용 그대로 복사하고, 날짜 자동 진행은 별도 생성 기능으로 구분한다.

미정: 최대 개수, 여러 페이지 선택 시 복제 단위, 복제본 간 공통 디자인 연결 여부, 대량 생성 시 성능과 진행 표시.

### A13. 공통 색상 팔레트

#### 사용자 요청

- 색상을 좌측 하단에 따로 배치해 관리한다. 위치와 접근 방식은 포토샵을 참고한다.
- 기본 컬러는 블랙 계열로 둔다.
- 포인트 컬러를 원하는 만큼 추가한다.
- 포인트 컬러는 A·B·C 같은 식으로 구분한다.
- 색상 변경을 쉽게 한다.

#### 설계 제안: 작업 팔레트와 연결 색상

```text
작업 색상
● 기본   ● A   ● B   ● C   ＋
```

- 기본색: 글자·선에 사용할 검정 또는 차콜.
- 포인트 A/B/C: 사용자가 추가·편집하는 색상.
- 요소는 실제 색상값 대신 기본/A/B 등의 색상 역할에 연결할 수 있다.
- A의 색을 바꾸면 현재 작업에서 A에 연결된 요소가 함께 바뀐다.
- 색상에 ‘제목’, ‘체크박스’ 등의 별명을 붙이는 방식을 검토한다.
- 팔레트는 현재 작업 단위로 관리한다. 다른 저장 작업을 자동 변경하지 않는다.
- 결정 (2026-09-28): Library → Colors에 팔레트를 저장해 둘 수 있다. 편집기에서 ‘팔레트 불러오기’를 하면 현재 작업에 **복사**된다. Library의 팔레트를 나중에 고쳐도 이미 만든 작업은 바뀌지 않는다.

#### 결정 (2026-09-28) — 모양과 색 고르기

패널 아래에 고정한다. 이전 시안(회색 5칸 + POINT `+` 칸)을 참고하되 모양은 새 UI에 맞춰 다시 그린다.

```text
작업 색상
기본  ■ ■ ■ ■ ■          ← 블랙 계열 5단계, 고정
POINT  A ●  B ●  ＋      ← 사용자가 추가·편집
```

- **기본**: 블랙 계열 단계. 고정 색이며 편집하지 않는다.
- **POINT A·B·C…**: 색 역할. A를 바꾸면 A에 연결된 요소가 함께 바뀐다(아래 표).
- **색을 고르는 과정에 확인 단계를 둔다.** 지금은 고르는 즉시 추가되어 불편하다.
  1. `＋`나 A를 누르면 색 선택 창이 열린다.
  2. 색을 고르는 동안 **미리보기**로 보인다. 아직 저장되지 않는다. A를 편집하는 중이면 A를 쓰는 요소도 미리보기로 바뀐다.
  3. **저장 버튼을 누르거나 창 밖을 눌러 나가면 확정**한다.
  4. 취소 버튼(또는 Esc)은 원래 색으로 되돌린다.

#### 적용과 편집 구분

| 동작 | 제안 결과 |
|---|---|
| 요소를 선택한 뒤 A 클릭 | 선택 요소에 A 연결 |
| A의 색상 편집 열기 | 현재 작업에서 A를 사용하는 요소의 색 변경 |
| 개별 색상 지정 | 해당 요소를 공통 팔레트와 독립적으로 관리 |

전체 변경 시 ‘A · 12개 페이지에서 사용 중’처럼 영향 범위를 표시하는 방식을 검토한다. 색상은 색만으로 구별하지 않고 기본/A/B 등의 문자도 함께 표시한다.

#### 가져온 페이지와의 관계 — 검토안

다른 작업에서 페이지를 가져올 때 현재 작업의 기본/A/B에 연결하면 여러 양식의 색감을 통일하기 쉽다. 다만 서로 다른 작업에서 A의 의미가 다를 수 있으므로 자동 연결을 확정하기 전에 규칙을 정해야 한다.

미정:

- 기본색도 변경할 수 있는지, 기본색의 초기값.
- 사용 중인 포인트 색상 삭제 시 다른 색상으로 대체하는 방식.
- 많은 색상이 생겼을 때 펼침·스크롤 방식.
- 새 요소를 만들 때 적용할 활성 색상.
- 선·채움·글자 등 여러 색상 속성을 가진 요소의 적용 대상.
- 기존 직접 지정 색상을 팔레트에 연결하는 방법.
- 가져온 페이지의 원래 색 유지와 현재 작업 색 적용 선택.
- 특정 페이지에서만 A를 다른 색으로 쓰고 싶은 경우의 처리.
- 전체 변경 미리보기와 실행 취소 범위.

### A14. Print — Create의 후반 액션

#### 결정 (2026-09-28) — 화면 구성

**별도 화면**으로 둔다. Rings는 종이 위 배치를 눈으로 확인하는 것이 중요해서 Canva식 작은 다운로드 창으로는 부족하다. Print는 **종이에 어떻게 찍을지만** 다룬다 — 반복·날짜 세트, 칸 배정, 칸 직접 고치기는 편집기로 옮기거나 없앴다.

```text
┌ ← 편집으로 · 10월 다이어리 ···································· [Export PDF] ┐
│ Paper │ Sides │ Layout │ Marks │                                              │
│───────────────────────────────│        ┌─────────────────────┐              │
│ (고른 하위 탭의 설정)           │        │   종이 미리보기      │              │
│                               │        └─────────────────────┘              │
│                               │         1장 앞면   ‹  1 / 9  ›  [앞|뒤]        │
└───────────────────────────────┴─ 33페이지 → A4 9장 (양면) · 속지 4개/장 ─────┘
```

| 하위 탭 | 내용 (지금 앱에서 온 것) |
|---|---|
| Paper | 출력 범위(전체 / 페이지 선택 — 신규), 크기, 방향, 여백, 인쇄 불가 가장자리 |
| Sides | 단면/양면, 뒷면 왼쪽, 뒷면 반 바퀴 |
| Layout | 간격, 90도 돌려 더 넣기, 정렬 / 고급: 자른 뒤 쌓는 순서, 무더기 장수 |
| Marks | 절취선, 50mm 검증 눈금, 출력 면 |

- **출력 범위 선택**(신규): 전체 / 페이지 선택. ‘10월만 다시’, ‘한 장만 다시’를 위해.
- **‘실제 인쇄 모습만’이 기본으로 켜져 있다.** 도트·타공 같은 화면용 안내는 기본으로 끈다.
- 하단에 **필요한 종이 장수**를 늘 보여준다.
- 미리보기에서 속지를 누르면 ‘이 페이지 편집’으로 편집기의 그 페이지로 돌아간다.
- 양면 뒤집기 테스트용 인쇄물은 Print가 아니라 **Learn**에 둔다(C 참고).


#### 설계 제안

제작 화면에서는 앞뒤 페이지의 논리적인 짝을 관리하고, Print에서는 프린터의 단면·양면 출력 조건을 설정한다.

- 앞뒤 한 쌍의 복제·이동 시 짝을 유지한다.
- 필요할 때 앞뒤를 나란히 볼 수 있는 보기 방식을 검토한다.
- 인쇄 용지에 여러 속지를 배치해도 제작 화면의 페이지 순서는 유지한다.
- 출력 조건: 용지 크기, 양면, 용지 위 배치, 재단선, PDF 내보내기.
- Print에서 내용 수정 시 해당 페이지의 제작 화면으로 복귀한다.

미정: 단면 페이지와 양면 세트를 섞을 때 빈 뒷면 처리, 홀수 페이지 출력, 수동 양면 인쇄, 짝의 일부 삭제 시 처리.

설정 순서는 출력 범위 → 용지 크기·방향 → 단면/양면 → 배치 미리보기 → 재단선 → PDF로 제안한다. 배치 간격·자동 회전·정렬·재단 후 쌓는 순서·무더기·검증 눈금은 필요에 따라 고급 설정에 둔다. 실제 크기 출력 안내와 인쇄 불가 영역을 보존한다. 출력 칸 배정과 내용 편집의 역할은 분리하며, 여러 저장 작업을 한 용지에 조합하는 기존 활용을 새 페이지 구조에서 어떻게 보존할지 추가 검토한다.

### A15. 검토 순서와 구현 전 확인

1. 화면 스케치에서 왼쪽 삽입 패널과 상단 꾸미기 바의 역할 분리 검토.
2. 오토필드의 종류 선택·형식 예시·날짜 연결 UI 검토.
2. 공통 글자 패널: 굵게 제거 범위, pt·mm, 줄간격·자간 검토.
3. 나머지 도구의 세부 항목 순서와 기본/고급 구분 검토.
4. 페이지 생성·복제·가져오기·팔레트의 공통 수정과 개별 수정 경계 확정.
5. 기존 데이터의 외형 보존, 자간과 단위의 화면/PDF 일치, 저장 후 재열기를 구현 검증 항목으로 지정.

이번 작업은 문서 계획이며 UI 구현, 데이터 변환, 기능 삭제를 실행하지 않는다.

## B. Library — 현재 합의와 연결 범위

내 작업(폴더) / 이미지 / 글꼴을 관리한다. 이번에는 Create와 연결되는 범위만 기록하며 전체 화면 상세 설계는 후속 논의한다.

### B1. 사용자 요청

이미지와 글꼴 파일 관리도 Library 메뉴에 포함한다.

### B2. 설계 제안

- 결정 (2026-09-28·10-01): Library 안쪽 탭은 **Projects / Diaries / Images / Fonts / Colors**. Diaries는 내 다이어리 등록·실측 수정·기본 바꾸기. Projects의 규격 필터는 **다이어리 필터**가 된다.
- 결정 (2026-10-01): 폴더는 **한 단계만**(폴더 안에 폴더 없음). 삭제한 작업은 **휴지통**으로 가고 **30일 뒤 완전히 지운다**. 그 전에는 되살릴 수 있다. 메뉴 이름은 작업 외 자료도 담으므로 Library로 유지한다.
- 내 작업은 한 목록이고 폴더로 정리한다(첫 버전부터). 썸네일에 페이지 수를 표시한다. 작업 카드에서 바로 Print로 갈 수 있다.
- 이미지 파일 목록과 미리보기를 확인하고 편집기에서 페이지에 삽입할 수 있게 한다.
- 등록한 글꼴과 미리보기를 확인하고 편집기의 글꼴 선택에서 사용할 수 있게 한다.
- 편집 중 자료를 사용할 때마다 Library로 이동하지 않고 해당 도구에서 바로 선택할 수 있게 한다.

미정: 등록·이름 변경·삭제 UI, 파일 형식·용량, 중복 처리, 사용 중인 파일 삭제가 기존 작업에 미치는 영향, 저장 위치와 동기화. Library에 포함한다는 합의가 클라우드 업로드나 계정 기능 도입까지 의미하지는 않는다.

## C. Learn — 후속 설계

현재 방향은 시작 안내, 사용 가이드, 규격·종이·바인더 참고 자료, 인쇄 안내를 담는 것이다.

결정 (2026-09-28): Learn은 블로그 형태(기본계획 6장). 여기에 **내려받아 뽑아보는 테스트 인쇄물**을 둔다.
- 양면 뒤집기 테스트: 앞뒤에 화살표만 찍힌 한 장. 뽑아서 ‘뒷면 반 바퀴’를 켤지 판단한다.
- 글자 견본: 글꼴 크기·굵기를 실제 인쇄 크기로 한눈에 비교하는 한 장. 세부 탐색 구조·콘텐츠는 아직 확정하지 않았다. 이번 Create 분석 범위에서 임의로 확대하지 않는다.
