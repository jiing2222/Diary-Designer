# 추가 기능 후보

작성일: 2026-10-11  
상태: 사용자 요청 목록 + 구현 가능성 분석. 넣을 단계는 아직 정하지 않았다.  
관련 문서: [기본계획.md](./기본계획.md) · [세부계획.md](./세부계획.md) · [디자인.md](./디자인.md)

난이도는 지금 코드 기준의 대략적인 크기다. **하** = 기존 기능을 조금 넓힘, **중** = 새 종류를 하나 더함, **상** = 여러 층(core·화면·PDF·저장)을 함께 바꿈.

CLAUDE.md 원칙을 따른다 — 새 객체 종류는 `isXxx` 판별 함수와 두 뷰(화면·PDF)의 레이어를 하나씩, 새 속성은 core에 `xxxOf`를 먼저 만든다. 화면과 PDF가 같은 결과를 내야 하는 것은 core가 한 번만 계산한다.

## 1. 손그림 선

일자선 대신 손으로 그은 것처럼 살짝 불규칙한 선.

- **가능. 난이도 중.**
- 선 모양(실선·파선·점선)에 ‘손그림’을 하나 더한다. 곧은 선을 잘게 나눠 조금씩 흔든 경로를 core에서 만든다.
- **흔들림은 매번 같아야 한다** — 화면을 다시 그리거나 PDF로 뽑을 때마다 모양이 바뀌면 안 된다. 객체 id를 씨앗으로 한 고정된 난수를 쓴다.
- 흔들림 정도(약하게·강하게)를 고를 수 있게 할지는 검토.

## 2. 도트 객체

표처럼 영역을 잡아 도트를 그린다. 도트 크기를 하나하나 조정할 수 있다.

- **가능. 난이도 중.**
- 새 객체 종류(`isDots`). 가로·세로 개수, 간격, 기본 도트 크기, 색.
- ‘하나하나’ 크기 조정은 바꾼 도트만 기억한다(나머지는 기본 크기를 따름 — CLAUDE.md의 ‘값이 없으면 기본값’ 원칙과 같다).
- 속지 바탕의 도트 격자(Page → Background)와는 별개 — 이쪽은 원하는 곳에 놓는 객체다.

## 3. 그려서 넣기 (긴급도 낮음)

그림판처럼 마우스·펜으로 그려서 넣는다.

- **가능. 난이도 중~상.**
- 새 객체 종류(`isStroke`): 펜이 지나간 점들을 매끄럽게 이은 경로.
- 지우개, 굵기, 필압(펜 태블릿)을 어디까지 할지에 따라 커진다. 첫 판은 ‘그리기 + 굵기 + 되돌리기’만.
- 1번(손그림 선)과 경로 그리기 부분을 함께 쓸 수 있다.

## 4. 자 (눈금자) 토글

편집 화면 위쪽과 오른쪽에 mm 눈금자를 켜고 끈다(참고: 사진의 PDF 편집기 눈금자).

- **가능. 난이도 하.**
- 화면에만 보이고 인쇄되지 않는다.
- 확대·스크롤과 함께 움직여야 한다. 선택한 객체의 위치를 눈금자 위에 표시하면 더 좋다.
- 지금 Print의 ‘50mm 검증 눈금’(인쇄되는 것)과는 다르다.
- 위치 질문: 위·오른쪽으로 할지, 일반적인 위·왼쪽으로 할지. 왼쪽은 레일·패널과 붙어 있어서 오른쪽이 나을 수 있다.

## 5. 맞춤 안내선 (스마트 가이드)

객체를 옮길 때 페이지 중앙이나 다른 객체의 가장자리·중앙에 맞으면 안내선이 뜨고 달라붙는다.

- **가능. 난이도 중.**
- 지금 도트에 달라붙기(`core/snap.ts`)가 있다. 여기에 ‘다른 객체·페이지 중앙’ 후보를 더하고, 끄는 동안 안내선을 그린다.
- 도트 달라붙기와 객체 맞춤이 동시에 걸릴 때 무엇을 우선할지 정해야 한다(예: 객체 맞춤 우선, Alt를 누르면 끔).

## 6. 인덱스 (속지 오른쪽 탭)

속지 오른쪽 바깥으로 튀어나온 인덱스 탭. 크기와 개수를 넣으면 자동으로 나눠 배치하고 자르는 선을 그린다.

- **가능. 난이도 상.**
- 속지 크기 + 탭 폭이 실제로 잘라야 할 모양이 된다. Print의 배치(한 종이에 몇 개), 재단선, 양면 인쇄에서 뒷면 탭 위치(반대쪽)까지 함께 바뀐다.
- 여러 페이지에 걸쳐 탭이 계단식으로 내려가는 것(1번 탭은 1월, 2번 탭은 2월…)을 원하는지 확인이 필요하다.
- 탭에 글자(월 이름 등)를 넣을지, 그 글자가 오토필드와 연결되는지도 확인.
- 인쇄 정확도가 중요해서 **실제 인쇄로 검증해야 하는 값**이 생긴다(진행상황.md ‘아직 인쇄해보지 않은 값’).

## 7. 오토필드 — 페이지 번호·숫자, 날짜를 코드로

- **페이지 번호**: 이미 계획됨(세부계획 A4.7). **난이도 하.**
- **숫자 옵션**: 시작값·증가값을 정해 1, 2, 3… 또는 001, 002… 처럼 매기는 것. 페이지 번호와 달리 날짜·페이지와 무관하게 셈. **난이도 하.** 어디에 쓰려는지 확인 필요.
- **날짜를 코드로**: `YYMMDD`, `YYYY.MM.DD (ddd)` 처럼 형식 코드를 직접 쓰면 그대로 바뀐다. **가능. 난이도 하~중.**
  - 예시 칩(타일)은 그대로 두고, 맨 아래에 ‘직접 입력’ 칸을 두는 방식. 입력하는 대로 실제 날짜 미리보기를 보여준다.
  - 앞서 없애기로 한 `<+D0>`(글자 안에 자리표시를 쳐서 필드 만들기)와는 다르다 — 이것은 오토필드 패널 안에서 **형식**만 코드로 정하는 것.

## 8. 일렬 보기 / 펼침면 보기 토글

- **가능. 난이도 하~중.** 편집 화면의 페이지 배치만 바뀐다.
- 일렬 보기: Canva처럼 한 면씩 아래로. 펼침면 보기: 지금 결정한 다이어리 펼친 모습.
- 하단 상태 막대에 토글을 둔다.

## 9. 타공 위치 표시 — 크기 선택

- **가능. 난이도 하.** 지금도 화면에 구멍 위치를 표시하는 기능이 있다(규격마다 4mm·6mm로 고정, 인쇄되지 않음).
- 구멍 지름을 3~6mm, 0.5mm 단위로 고르게 한다. 다이어리 설정(Library → Diaries)에 둔다.
- **인쇄물에도 표시할지** 확인 필요 — 손으로 타공할 때 위치 표시가 인쇄되면 편하다.

## 10. 긴 글 텍스트 상자 — 다음 면으로 이어짐 + 마크다운

- **가능. 난이도 상.** 목록에서 가장 크다.
- 글이 상자를 넘치면 같은 양식의 페이지가 뒤에 자동으로 생기고, 넘친 글이 그 페이지의 같은 상자로 이어진다.
- **글자 줄바꿈이 화면과 PDF에서 똑같아야 한다.** 지금은 화면은 브라우저로, PDF는 pdf-lib로 글자 폭을 따로 잰다. 이어지는 글에서는 한 줄만 달라도 페이지가 밀린다 → 글자 폭 측정을 core에서 한 번만 하도록 먼저 바꿔야 한다. (자간 추가 때도 필요한 일이라 같이 하면 좋다.)
- **마크다운**: 제목, 목록, 체크박스 정도의 일부만 지원하는 것을 제안. 굵게(`**`)는 **굵게 버튼을 없애기로 한 결정**(세부계획 A4.5)과 부딪힌다 — 마크다운에서는 굵게를 허용할지 정해야 한다.
- 2단계: 이어지는 텍스트 → 3단계: 마크다운 순으로 쪼개는 것을 제안.

## 11. 작업 탭 (여러 작업을 탭으로 열기)

사진의 PDF 편집기처럼 여러 작업을 탭으로 열어 오간다.

- 1~10번을 정한 뒤 따로 검토한다(2026-10-11 사용자).
