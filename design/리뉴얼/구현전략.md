## 1. 판단 — ‘상’ 기능은 첫 버전에서 빼되, 바닥은 미리 깐다

두 안을 비교했다.

| | 안 1: 기능후보 전부 함께 | 안 2: ‘상’(인덱스·긴 글) 빼고 |
|---|---|---|
| 첫 버전까지 | 길다. 인덱스는 Print·재단·양면을, 긴 글은 글자 측정·페이지 자동 생성을 함께 바꾼다 | 짧다 |
| 인쇄 검증 | 인덱스 탭 위치·재단선·가짜 굵게 굵기 등 실제 인쇄로 확인할 값이 한꺼번에 쌓인다 | 가짜 굵게·자간 정도 |
| 위험 | 한 단계가 길어져 ‘단계마다 써볼 수 있는 결과’를 지키기 어렵다 | 낮음 |
| 나중에 넣을 때 | — | 바닥을 미리 깔아두면 다시 뜯지 않는다 |

**안 2를 추천한다.** CLAUDE.md의 ‘빠른 완성 우선’에 맞고, 두 ‘상’ 기능이 바꾸는 범위(Print 배치, 글자 흐름)가 넓어 다른 기능과 엉키기 쉽다. 대신 **나중에 다시 뜯지 않도록 바닥 두 가지는 첫 버전에서 미리 만든다.**

1. **글자 측정을 core 하나로** — 화면(브라우저)과 PDF(pdf-lib)가 따로 재던 글자 폭을 한 곳에서 잰다. 자간 추가에 어차피 필요하고, 긴 글 이어짐(10)의 전제다.
2. **Print 배치가 ‘속지 = 직사각형’을 가정하지 않게** — 속지가 차지하는 영역을 core에서 물어보게 해 두면, 인덱스(6)가 ‘속지 + 탭’ 영역을 돌려주기만 하면 된다.

## 2. 순서를 정한 원칙

1. **데이터 구조가 먼저.** 여러 페이지 작업, 요소 단위 개별 수정, 색 역할(A·B), 탭(여러 작업 동시에 열림)은 모두 저장 형식을 바꾼다. 화면부터 만들면 저장 형식이 바뀔 때 다시 고친다. 저장 형식은 **한 번에** 바꾸고, 옛 데이터 옮기기도 한 번만 한다.
2. **core → 화면·PDF.** 새 속성·새 객체는 core에 판단(`xxxOf`, `isXxx`)을 먼저 만들고 두 뷰가 부른다(CLAUDE.md).
3. **단계마다 실제로 써볼 수 있게.** 옛 화면은 새 화면이 대신할 때까지 남긴다(예: 6단계 전까지는 옛 Print로 뽑는다).
4. **기능 추가는 뼈대가 선 뒤.**

## 3. 단계

| 단계 | 내용 | 끝나면 써볼 수 있는 것 |
|---|---|---|
| **0. 준비** | `feat/rings-print-2`·`feat/auth`를 main에 합치기, `renewal` 브랜치, Notebook 태그. 새 색·글꼴(Jost·Pretendard)을 지금 앱에 입히기 | 지금 앱이 새 색·글꼴로 |
| **1. 데이터 구조** | 작업 = 여러 페이지(펼침면), 내 다이어리(±10mm 규격 인식), 작업 색 역할(기본·POINT A·B…), 날짜 페이지와 **요소 단위** 개별 수정, **여러 작업 동시에 열림**(탭 전제). 새 저장소 + 옛 데이터 복사(기본계획 8-1). 대부분 core·store와 테스트 | 옛 양식이 새 구조로 옮겨져 열림. 한 작업에 페이지 추가·복제·삭제 |
| **2. 앱 틀과 탭** | ㄱ자 틀, 고정 Library 탭 + 작업 탭(10개), 탭별 되돌리기·스크롤·선택 기억, 로고 → 토성 홈 | 여러 작업을 탭으로 오가며 복붙 |
| **3. 편집기** | 레일(Select·Page·Draw·Text·`{ }`·Image, 맨 아래 Colors), 상단 꾸미기 막대(자리 고정), 다이어리 칩, 하단 치수 막대, **펼침면/일렬 토글(8)**, 페이지 관리·한눈에 보기, 둥근 커서 | 새 편집기에서 지금 기능 전부 |
| **4. 날짜와 AutoField** | 편집기에서 날짜 페이지 만들기, 실제 값 표시, 공백/이어서(월·주 경계), `<+D0>` 입력 제거, Year·주간 범위·Page No.·D-day·Moon(8단계), **형식 코드(YYMMDD·n/nn/nnn)(7)**, AutoField 선택 테두리 | 10월 데일리 31장 만들고 10/5만 바꾸기 |
| **5. 글자** | **글자 측정 core로 통일(바닥 1)**, 자간 mm, B·I·U·S(가짜 굵게), 글자 스타일 저장 | 자간·굵게가 화면과 PDF에서 같게 |
| **6. Print** | 새 Print 화면(탭 안), Paper·Sides·Layout·Marks, 출력 범위, 모든 장 보기, 칸 배정 제거, **배치의 영역 추상화(바닥 2)**, PDF 전 확인 창(타공·격자), **타공 표시 크기·인쇄 옵션(9)** | 새 화면에서 PDF |
| **7. Library와 온보딩** | Projects(폴더·휴지통 30일·다이어리 색 점·다른 다이어리로 복제), Diaries, Images(최신순)·Fonts(가나다·즐겨찾기), 목록에서만 지우기, Colors(팔레트 저장·불러오기), 다른 작업에서 페이지 가져오기, 첫 다이어리 온보딩, Learn ‘준비 중’ | 앱 전체를 새 구조로 |
| **8. 로그인·클라우드** | `feat/auth`의 로그인·계정을 새 틀에 붙이고, 서버를 **작업마다 한 칸**으로 다시 짠다(폴더·휴지통·다이어리·팔레트 포함) | 다른 기기에서 이어서 |
| **9. 편집 편의** | 눈금자 토글(4), 맞춤 안내선(5), 손그림 선(1), 도트 객체(2) | 기능별로 하나씩 |

**첫 버전 이후 (안 2에서 뺀 것)**: 인덱스(6) · 긴 글 이어짐 → 마크다운(10) · 그려서 넣기(3) · Notebook 되살리기(Create 하위) · Learn 글 · 공휴일·음력 · 손맛 일러스트 · 터치 기기

1~9가 끝나면 첫 버전이다. 9는 기능마다 독립적이라 순서를 바꾸거나 일부를 첫 버전 뒤로 미뤄도 된다.

## 4. 서로 부딪힐 수 있는 지점과 대응

| 지점 | 문제 | 대응 |
|---|---|---|
| 날짜 개별 수정 × 색 역할 | 10/5에서 바꾼 색이 A 역할인지 직접 색인지 | 개별 수정도 ‘바꾼 속성만’ 기억한다. 역할로 고르면 역할을, 직접 고르면 색값을 기억 — 일반 요소와 같은 규칙 |
| 날짜 개별 수정 × 원본 수정 | 원본을 고쳤을 때 개별 수정한 속성은? | 개별 수정한 **속성만** 원본을 따르지 않는다(요소 전체가 아니라). 1단계 테스트로 못박는다 |
| 날짜 개별 수정 × 기간 바꾸기 | 수정이 몇 번째 페이지에 붙어 있나 | 페이지 번호가 아니라 **날짜**에 붙인다. 기간을 바꿔도 같은 날짜면 수정이 따라간다 |
| 다른 작업에서 페이지 가져오기 × 날짜 페이지 | 가져온 날짜 페이지의 연결 | 가져오면 복사본. 날짜 규칙은 가져오고 기간은 새로 정한다(세부계획 A6) |
| 탭 × 되돌리기 | 한 탭의 되돌리기가 다른 탭을 건드림 | 되돌리기 기록을 작업마다 따로 둔다(1단계 store 구조) |
| 탭 × 저장 | 열린 작업 여러 개를 언제 저장하나 | 작업마다 따로 자동 저장. 바뀐 작업만 |
| 가짜 굵게 × 줄바꿈 | 굵게 하면 줄이 밀릴까 | 가짜 굵게는 글자 폭을 바꾸지 않는다 — 밀리지 않는다 |
| 자간 × 화면/PDF | 두 곳의 글자 폭이 달라 줄바꿈이 어긋남 | 5단계에서 측정을 core 하나로(바닥 1) |
| 펼침면 × 단면 작업 | 뒷면이 없는 작업의 펼침면 | 작업마다 양면/단면. 단면이면 일렬 보기가 기본 |
| Select 유지 × 맞춤 안내선 × 도트 달라붙기 | 무엇에 붙나 | 9단계에서 우선순위를 정한다(객체 맞춤 우선, 키로 끄기) |
| 로컬 저장 × 클라우드 | 어느 쪽이 새것인가 | 작업마다 수정 시각을 비교(지금 `feat/auth`의 `remoteIsNewer`를 작업 단위로) |
| 옛 버전 × 새 버전 | 같은 브라우저에서 둘 다 켬 | 새 버전은 새 저장소, 옛 저장소는 읽기만(기본계획 8-1) |
| 인덱스(나중) × Print | 속지가 직사각형이 아님 | 6단계에서 배치를 영역 추상화(바닥 2) |

## 5. 단계마다 지킬 것

- 단계를 시작하기 전에 구조를 설명하고 동의를 받는다(CLAUDE.md).
- 단계가 끝나면 테스트·타입 검사·빌드를 통과시키고, 진행상황.md를 갱신하고 커밋한다. 화면 확인은 사용자가 한다.
- 인쇄해봐야 아는 값(가짜 굵게 굵기, 자간, 타공 표시 크기 등)은 진행상황.md ‘아직 인쇄해보지 않은 값’에 적고 묻는다.
- 새 객체 종류는 `isXxx` + 두 뷰 레이어, 새 속성은 core `xxxOf`부터.
